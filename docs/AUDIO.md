# 오디오 생성 · 검수 메모

- 엔진: ElevenLabs `eleven_multilingual_v2`
- 영어 목소리: **Jessica** (premade, "Playful, Bright, Warm", American) – 속도 0.9 (문장 0.85)
- 한국어 안내 목소리: **Annie KR** (Seoul, young)
- 후처리: ffmpeg 무음 제거 + 라우드니스 정규화(-16 LUFS) → mono 64 kbps mp3
- 파일 수: 단어 548 · 문장 210 · 음소 45 · 글자 이름 26 · 칭찬/효과 문구 18 · 한국어 안내 22 = **869개 (약 7.9 MB)**
- 브라우저 TTS(speechSynthesis)는 사용하지 않아요. `manifest.json` 에 없는 소리는 재생하지 않아요.

## 검수 방법

1. Whisper(base.en) 로 전 파일 받아쓰기 → 불일치 118개 추출 (대부분 동음이의어·숫자 표기·짧은 단어 오인식)
2. 불일치 단어와 모든 음소를 wav2vec2 음소 인식기(`facebook/wav2vec2-lv-60-espeak-cv-ft`)로 IPA 확인
3. 실제 문제였던 것 재생성: `sea`(say처럼 들림), `cane`(can처럼 들림), `boot`(boat처럼 들림), `hog`, `hop`, `I`
4. 단일 글자 TTS("E.")가 불안정해서 → 글자 이름은 알파벳 낭독("A. B. C. …")을 녹음해 쉼 구간으로 분리

## 음소 v3 (2026-11-15 저녁) — 출처 변경

- **a–z 26개 낱소리는 [Open Letter Sounds](https://github.com/purplecomputerorg/openlettersounds) (CC0 1.0)** 로 교체했어요. 파닉스용으로 만든 소리(짧은 a = apple의 /æ/, o = octopus의 /ɑ/, 'buh' 없는 파열음, 0.55–0.7초로 늘인 지속음)이고 작성자가 직접 귀로 검수한 클립이에요. 우리 형식(앞 80 ms·뒤 150 ms 여백, 음량)만 맞췄어요.
- v2의 짧은 a는 'baa'에서 잘라서 b가 섞이고 /ɑ/에 가까웠어요(“빠/바”). → OLS a: F1≈1107 Hz, F2≈1858 Hz (= /æ/).
- OLS에 없는 소리만 ElevenLabs: ch dh ng nk sh th, 그리고 모음팀 oo ow oi aw ar or er uu — 모음은 **앞에 자음이 없는** 단어(Ooh!, Ow!, Oy!, awe, are, ore, err)에서 모음 부분만. uu(/ʊ/)는 모음으로 시작하는 단어가 없어 "wood"의 가운데만 사용.
- vocamax/ipa-audios는 검토만 하고 **사용하지 않았어요**: 저장소 스스로 "업로더가 표시한 CC BY 3.0, 원 출처 미확인 (자음 영상은 다른 곳 녹음을 모은 것처럼 보임)"이라고 적고 있어서 재배포 권리가 확실하지 않아요.
- 확인 도구: `tools/vowel_check.py` (wav2vec2 음소 인식 + LPC 포먼트). 고립된 모음에서는 인식기가 æ/ɛ/ʌ를 모두 'a(ː)'로 적는 등 신뢰도가 낮아서 포먼트를 함께 봤어요.

## 음소(낱소리) 만드는 법 — v2 (2026-11-15 개선, 일부는 v3에서 교체됨)

v1은 단어에서 아주 짧게 잘라내서 "뚝 끊기는" 느낌이 있었어요. v2에서는:

1. **전용 녹음** – ElevenLabs가 혼자서도 잘 내는 지속음은 따로 녹음했어요: `Mmmmmm.` `Nnnnnn.` `Ssssss.` `Shhhhh.` `fffff` `thhhh`(eleven_v3) `Zzz.` `hhhhh`. 음소 인식기 + 스펙트럼(고주파 비율, 유성음 여부)으로 모음이 섞이지 않은 것만 골랐어요. (`Llllll`, `Rrrrr`, `Vvvvv`, `Eh/Ih/Uh` 같은 시도는 모음이 섞이거나 다른 소리로 읽혀서 탈락)
2. **단어에서 자르되 자연스럽게** – 나머지는 단어 녹음에서 잘라내지만
   - 파열음 b d g p t k c ch j: 터지는 소리 + 기식 + **아주 짧게 사라지는 약한 모음 꼬리**(30–80 ms 페이드). 'buh'처럼 길게는 아님. 운반 단어는 bug, duck, gum, jug, pup, tub, cup, cut, chug.
   - 모음: 'h/b + 모음' 단어(baa, heh, hiss, hah, huh, hood, how, who, boy, saw, are, or, her)에서 큰 모음 구간만 쓰고 자연스러운 감쇠를 살림.
   - v, dh, l, ng, r: 정상 구간을 WSOLA(ffmpeg atempo)로 0.25–0.65초까지 늘림.
3. **공통 마감** – 코사인 페이드 인(25–60 ms)·아웃(45–120 ms), 앞 80 ms·뒤 150 ms 무음 여백, RMS 기준 음량 정규화.
4. 지속음 길이: m 0.74 · n 0.69 · s 0.68 · sh 0.67 · f 0.63 · th 0.65 · l 0.59 · ng 0.56 · z 0.52초.
5. 글자 이름(26개): 끝이 잘리지 않았는지 측정(끝부분이 최고 음량의 1–4%까지 자연 감쇠) → 끝을 최대 150 ms 더 살리고 80 ms 페이드 + 여백 100 ms로 다시 만듦.

이번 개선에 쓴 크레딧: 약 **207** (계정 카운터 55,902 → 56,109).

## 🔎 사람 귀로 한 번 확인해 주세요

- **v, dh**(this의 th): 원래 약한 소리라 늘려도 0.25/0.17초로 짧은 편이에요.
- **z**: 짧은 녹음(0.2초)을 늘린 것이라 살짝 기계적일 수 있어요.
- **b, d, g**: 약한 모음 꼬리가 있어요(의도). 너무 '버/더'처럼 들리면 알려주세요.
- **r, w, y**: 활음이라 뒤 모음이 살짝 섞여 있어요.
- **e, i**(짧은 모음): 0.37초. 서로 비슷하게 들리지 않는지.
- **ng**: 늘린 소리라 살짝 울리는 느낌일 수 있어요.
